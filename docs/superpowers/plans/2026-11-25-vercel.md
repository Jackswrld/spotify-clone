# Vercel-ready music server — design and plan

**Why:** the live site (https://spotify-clone-eight-opal-82.vercel.app) loads, but Top songs and Top
albums say "Can't reach the music server". Vercel serves the web page for `/api/*` because nothing
runs `server/`. Chart playback, lyric search and artist photos all depend on it.

**Approaches considered:**
- **The relay as one Vercel function, with Upstash Redis for the song→video memory.** Chosen by the user.
  Free, and every song costs one YouTube lookup ever, shared by all visitors.
- **The same, with no storage.** Simpler, but the memory resets often and the 100 daily lookups run out fast.
- **Hosting the relay elsewhere** (Render, Fly). This adds a second service and its own cold starts, and Vercel can already run it.

**Design (calls are mine unless noted):**
- `api/[...path].mjs` is a thin Vercel function that reuses `createRelay` from `server/relay.mjs`. It
  builds the relay once per warm instance. `npm start` locally is unchanged.
- **Song→video memory:**
  - `server/redis-cache.mjs` implements `createRedisMatchCache({ url, token, fetch })` over Upstash's REST API, with no new dependency.
  - Its get, set and delete are async. `matchSong` and the DELETE route `await` the cache, which works for both the file cache and the Redis cache.
  - "No match" entries get a Redis expiry of 7 days, the same rule as the file cache.
  - A Redis failure never breaks playback: a failed read counts as a miss, and a failed write is ignored.
- **Which memory is used:**
  - Redis when `KV_REST_API_URL`/`KV_REST_API_TOKEN` (set by Vercel's Upstash integration) or `UPSTASH_REDIS_REST_URL`/`UPSTASH_REDIS_REST_TOKEN` are set.
  - Otherwise the file cache locally.
  - Otherwise memory only, on Vercel without Redis.
- **Allowed origins:** localhost plus `https://` + `VERCEL_PROJECT_PRODUCTION_URL`, `VERCEL_URL` and
  `VERCEL_BRANCH_URL` (Vercel sets these), plus any `ALLOWED_ORIGINS` (comma-separated). Other
  websites are still refused.
- **Visitor IP for rate limits:** the first `x-forwarded-for` address when present (Vercel), else the socket address.
- **`vercel.json`:**
  - Pages are served from Angular's build output.
  - Everything that isn't `/api/…` or a file falls back to `index.html`, so deep links work.
  - `/api/*` goes to the function.
- **The user's steps in the Vercel dashboard** (only they can do these):
  1. Add `YOUTUBE_API_KEY` and `GENIUS_ACCESS_TOKEN` as environment variables.
  2. Add Upstash Redis (free) from Storage and connect it to the project.
  3. Redeploy, which the push does.

**Non-goals:** Last.fm on the live site (no key there, as locally); a user login.
